# BiliDesktop（开发中）

主界面右下角和托盘菜单中的“关于”显示 beta1 版本、开发者仓库以及最初参考的直播录制、视频下载和 API 项目链接；关于窗口置顶，标题栏只提供关闭按钮。

当前实现普通 BV 视频与分 P、视频搜索及分页、手动 Cookie 和扫码登录、DASH 音视频流选择，并使用 aria2 下载、FFmpeg 合并。标准视频链接中的 `p` 参数会定位到对应分 P。支持音视频、仅视频、仅音频和封面；可选择 MP4/M4A 或 MKV，以及流复制、软件 H.264、NVENC、QSV、AMF 转码。转码前会检查所选编码器是否可用。支持番剧 `ss`/`ep`、含 BV 的 festival 链接，以及课堂 `cheese/play/ss...` 或 `cheese/play/ep...` 链接；课程分集按接口权限标记可观看状态。账号仅能获取试看时会显示提示，批量和自动任务不会将试看当作完整视频保存；受 DRM 保护或仅提供分段流的课程暂不支持。

对于视频详情标记为 UGC 付费的内容，程序还会查询播放器接口中的 `is_ugc_pay_preview`；该字段为真时按试看处理，字段缺失或类型异常时停止下载并提示无法确认。这一字段的实际行为及其他付费类型尚未使用真实付费视频充分验证，因此不能保证识别所有形式的试看或所有购买权限。

分 P 和 UGC 合集可选择条目批量下载；合集会展开每个视频的分 P。收藏夹入口可以切换账号创建的收藏夹和账号收藏的其他人的视频收藏夹，并选择视频批量下载；同一窗口支持添加和管理收藏夹自动备份规则。收藏的视频合集暂不包含在这个列表中。UP 主入口支持 UID 或主页地址并分页查询；曾在匿名实网测试遇到 HTTP 412，登录状态下已成功查询公开 UP 主的多页投稿。批量任务默认自动选择容器：无损音轨使用 MKV，其他音轨使用 MP4/M4A；也可手动指定格式。自动模式会检查两种容器的已有文件。单项下载、批量任务和自动规则共享全局最大并发下载任务数，可输入正整数或选择不限；超出上限的任务排队，取得下载槽位后才获取最新流地址，避免长时间排队导致地址过期。降低上限不会中断已运行的任务，直播录制不占用下载槽位。单项下载若所选画质或音轨不再可用，会提示重新解析。停止批量排队不会中断已开始的任务。单个任务的 aria2 分段上限为 64，同一服务器上限为 16，可设置每任务磁盘缓存；旧设置默认最多同时下载 4 个任务，每任务缓存上限随同时运行的任务数累加。现有文件不会被覆盖。支持 User-Agent 预设与自定义；登录信息可选择以 Windows 当前用户的 DPAPI 加密保存。扫码响应包含 SESSDATA 到期属性时显示并加密保存该时间；手动输入或缺少到期属性时显示未知。该属性不保证服务端会话不会提前失效。

程序启动时及运行期间每两小时检查公开 GitHub Release（含预发布版）；有新版时显示提示、版本、发布日期和发布说明，并可在浏览器中打开 GitHub Release 或备用下载页面。中国大陆时区依次尝试 GitHub 直连和设置的镜像源，全部失败时提示；请求不包含哔哩哔哩 Cookie，也不会自动下载或执行更新。版本标签支持 beta1、beta2、v1.2.3 和 v1.2.3-beta.1 等格式；没有 Release 时不提示更新。

搜索结果展示当前页的封面缩略图和播放量；单击视频可查看简介、发布时间及互动数据；点击详情中的 UP 主名称会按 UID 查询投稿并进入批量下载选择界面。翻页或关闭搜索时取消旧图片请求并释放预览，图片加载失败不影响搜索。

应用内的搜索、下载任务、收藏夹、直播及其他功能窗口可独立切换；文件选择和确认操作使用系统对话框。“允许后台运行”关闭时关闭主窗口会退出程序；启用时点击关闭会隐藏窗口到托盘。

界面可切换简体中文、繁体中文和英文，选择保存在本地；常用状态已翻译，部分动态错误、平台返回信息和系统对话框仍可能显示原文。支持 AV 号、标准 AV 视频链接及跳转到支持的视频或番剧地址的 b23.tv 短链接。API 返回杜比或无损音轨时会列入选择，编码与输出容器不兼容时 FFmpeg 可能报错；无损音轨已用公开视频测试批量下载、自动 MKV 混流与重复跳过，杜比音轨仍仅用模拟响应验证。本项目仍处于开发阶段。

选择“仅音频”时，单项和批量下载可分别勾选嵌入视频封面、将 UP 主写为歌手、将单个视频或分 P 名称写为歌曲名，以及将合集或视频总标题写为专辑名。M4A 使用内嵌封面图片，MKV 使用图片附件；合集或多分 P 音频的音轨编号按视频或分 P 的顺序写入；音频不因写入标签而转码。选中歌手但无法确认 UP 主时会提示错误；封面读取失败时任务会报错并保留临时文件，可重试或取消相应选项。不同播放器对 MKV 封面附件的支持可能不同。

视频清晰度和视频编码分别选择，音质单独选择；所选流的大小通过无 Cookie 的范围请求查询，服务器不提供长度时显示未知。显示的音视频流大小之和不包含混流后的容器开销。应用新 User-Agent 后会重新解析当前视频并尽量保持分 P。可设置并保存默认下载目录；分 P 和番剧默认按标题与视频标识建立子目录，视频文件名称参考下载姬的分集序号、标题、画质和编码；仅音频文件使用视频或分 P 名称，不附加画质或音质。单项下载仍可在保存对话框中修改路径和名称。

开始手动或批量下载时会打开下载任务窗口；下载任务和直播窗口各只保留一个，重复打开时恢复并激活已有窗口。“下载任务”窗口显示单项、批量以及收藏夹和关键词自动任务；合集中的分 P 分别显示。显示的是当前音频或视频流的进度、速度、连接数和预计剩余时间，不是音视频合计进度。可通过复选框或表头全选批量暂停、继续、取消和重试任务，打开文件或文件夹、移除记录，以及确认后永久删除已完成文件；没有勾选时操作当前选中行。各操作只处理状态适用的任务。暂停的传输释放并发槽位；FFmpeg 处理期间不能暂停，但可以取消。失败重试会重新获取流并从头下载，已完成记录保存在当前用户的本地应用数据目录，活动、失败和暂停任务仅在程序运行期间保留；退出或崩溃后不能续传。取消自动规则任务或删除其已完成文件后，规则仍可能在下次检查时再次安排它。

User-Agent 可选择 Windows、Android、iOS、iPadOS、macOS（含 Apple Silicon）和 Linux 浏览器预设，也可选择“自定义”并手动修改；点击“应用”后保存。Apple Silicon Chrome 预设采用浏览器常见的兼容性标识，其中仍可能显示 `Intel Mac OS X`，不能用它识别实际处理器。此设置用于视频 API 请求和下载；录播姬核心的直播请求使用其自带 User-Agent。

“自动备份”支持对自己创建或收藏的其他人的视频收藏夹添加、暂停、启用、删除和手动触发规则，检查间隔为 5 分钟至 24 小时。读取收藏夹后可为当前列表中的全部收藏夹一次创建规则；它们使用所选的同一目录和间隔，重复规则跳过而不修改已有设置。新规则会立即安排检查。规则与成功的分 P 记录保存在当前用户本地应用数据目录的 SQLite 数据库中；程序运行期间定期检查，重启后恢复。检查时必须登录规则所属账号；登录会话变化时停止继续排队。默认选择当前可用的最高画质和音质，顺序下载音视频并流复制合并；无损音轨使用 MKV，其他音轨使用 MP4。失败项下次重试。已登记的输出文件存在时跳过；未登记的同名 MP4 或 MKV 文件会报告并跳过，不会覆盖。删除规则不会删除下载的文件。不会因远端取消收藏而删除本地文件。程序退出后不执行备份；中断任务续传尚未实现。已登记文件仅检查存在，不定期验证其完整性。

“关键词监控”支持逐个添加多个关键词，并选择标题、简介或标签中满足任意关键词或全部关键词；每个关键词分别搜索，结果去重。检查间隔最短为 30 秒，也可选 1、2、3、5、15 分钟和 1、6、12、24 小时；间隔从本轮结束后计算。查询速率可选软件默认或更低，分别在搜索分页请求之间至少间隔 250 毫秒或 1.5 秒；多关键词会增加查询次数，较低速率不能保证不会被平台限制。遇到平台限流会延后重试。规则与下载记录保存在 SQLite 中，原有规则和已完成记录会保留。每条规则在所选目录中建立独立文件夹，文件名包含视频标题、画质、编码和用于区分的分 P 标识；无损音轨使用 MKV，其他音轨使用 MP4。已有旧版文件或同名文件时跳过。每个关键词最多检查平台返回的前 50 页，超过上限会提示，不能保证发现所有匹配视频。自动备份和关键词监控均仅在程序运行期间工作。

启用主窗口的“允许后台运行”后，点击关闭按钮会隐藏所有已打开的程序窗口，并在 Windows 通知区域显示程序图标；备份、关键词检查和直播录制继续运行。双击图标或使用图标菜单可恢复窗口，选择菜单中的退出可结束程序，有下载任务进行时会先询问是否中断。该开关会保存；关闭时，点击关闭按钮会退出程序。“登录时启动”会为当前 Windows 账户设置登录启动项，并以后台模式启动；取消勾选会移除当前版本的启动项。如果启动项指向旧版 BiliDesktop，勾选时会切换为当前版本；无法确认属于本程序的启动项不会被覆盖或删除。Windows 自身的启动设置或策略仍可能禁用该启动项；移动或删除程序后需重新设置。需要登录的备份规则还需要有效的已保存登录会话。

“直播”使用本地 BililiveRecorder 核心，支持直播间管理、自动或手动录制、目录选择和录制事件记录；房间配置不保存 Cookie。默认关闭按时间或大小切分。录制停止并等待 30 秒后，会尝试将同一房间、间隔不超过两分钟的相邻录制会话片段合并；仅当流参数、编码附加数据和时长检查通过时执行无损合并，原始片段始终保留。录制记录中也可手动选择同一房间的多个已关闭片段合并。新版会在录制文件打开时记录路径，异常退出后尝试登记录制目录内仍存在的片段，并按相邻会话分组整理所有待处理会话；对没有文件打开记录的旧会话无法自动定位丢失的路径。如果录制仍在继续，或记录不完整、编码不兼容、时长不可确认，则可能需要手动处理。网络中断造成的缺失不能恢复。这里仅接入录播核心及上述桌面功能，尚未集成上游全部界面、工具箱或配置项。录播姬源代码采用 GPL-3.0，随构建输出提供其许可证；分发时还需完成全部依赖和源码许可清单。

直播间支持数字 ID、`live.bilibili.com` 房间链接和跳转至该域名的 HTTPS `b23.tv` 短链接；添加后立即刷新主播、标题和开播状态，手动开始前也会刷新。界面提供标准或原始数据录制、画质等级及 AVC/HEVC 优先或单独选择，并可直接编辑与录播姬兼容的画质优先级。实际流取决于直播间和账号权限；当前录播核心选择 HTTP-FLV 的 AVC/HEVC 流，未实现 AV1 或其他协议，编码选择指直播源而非硬件解码。可选按时间、大小或标题变化分段，以及保存弹幕和封面；原始数据模式不支持分段。设置全局生效，录制中不能更改。已用公开直播间分别实测标准模式和登录状态下原始模式的短时录制；链接短跳转、全部画质及不同直播间权限尚未全部实测。

直播列表刷新时保留选中行和复选框；勾选多个直播间时，刷新、开始、停止、切换自动录制和移除操作作用于勾选项，未勾选时作用于选中行。录制使用系统 DNS 连接直播线路；某条线路连接失败或未返回有效 FLV 头时，会尝试平台返回的其他同画质、同编码线路，收到有效数据后才创建录制文件。连接与请求超时时间也已延长；所有线路不可用时仍会显示失败并按照录播核心逻辑重试。新产生的零字节文件会在录制记录中标记并保留，不参加自动合并；原有文件不会被自动删除。连接成功后仍可能因网络中断或写入错误产生不完整录制。

直播列表以文字区分开播、录制和自动录制状态，并显示录制期间的实时网络吞吐量（Mib/s）及录制速度百分比。百分比沿用录播姬的统计：收到的直播时长除以实际经过的时间，100% 表示跟上直播，并非下载进度；原始数据模式没有该统计。新开录、停止、数据过期或不可用时显示“—”。“打开录制目录”按钮打开当前设置的目录。

桌面端使用本地修改的录播核心，将主动刷新失败返回给调用方；手动录制遇到刷新失败时不采用上一次的开播状态。短链接重定向、域名和 HTTPS 限制已用模拟响应验证，真实短链接仍需更多样本。
添加直播间时会先以暂停自动录制的状态核验真实房间号，避免短号和长号重复时启动两份录制。核验失败的房间会保留在列表中且自动录制关闭，可稍后手动刷新并重新启用。画质优先级为自定义值时，预设选择框会留空，避免显示与实际设置不符的预设。

需要 Windows、.NET 10 桌面运行时，以及 ffmpeg 和 ffprobe；Windows x64 自包含预览构建不需要另外安装 .NET。音视频下载或录制片段合并前会检查媒体工具；先查找程序目录下 `vendor/ffmpeg`，然后查找本程序的本地缓存和系统 PATH。工具缺失时会自动下载约 110 MB 的 FFmpeg 9.0.2 Essentials 压缩包，显示下载进度，核对内置 SHA-256 后仅提取 ffmpeg、ffprobe 和 LICENSE 到当前用户的本地应用数据目录；不会修改系统 PATH。下载失败或超时会报告错误，可自行将工具放入 `vendor/ffmpeg` 或 PATH。固定版本 URL 失效后需要更新程序；软件不会自动升级已下载的 FFmpeg。单独下载封面不需要 FFmpeg。

FFmpeg 项目提供源码并在[下载页](https://ffmpeg.org/download.html)列出 Windows 构建来源；自动下载使用 [gyan.dev 构建](https://www.gyan.dev/ffmpeg/builds/)，该构建为 GPL-3.0，下载包附带许可证，其对应源码链接见构建提供方页面。分发 BiliDesktop 前仍须完成所有依赖的许可和源码清单。

开发环境可在仓库根目录执行：

```powershell
dotnet build BiliDesktop\BiliDesktop.csproj
dotnet run --project BiliDesktop
dotnet run --project BiliDesktop.Smoke
dotnet run --project BiliDesktop.LiveSmoke
dotnet run --project BiliDesktop.TraySmoke
```

aria2 来源于本工作目录 `downkyi/third_party/aria2-1.36.0-win-64bit-build1.zip`，其许可文本随二进制提供。二维码由 QRCoder 生成，其许可文本也随程序提供。音视频下载通过只绑定本机的带密钥 RPC 控制 aria2；Cookie 不传递给 CDN，可选择加密保存到当前用户的本地应用数据目录。若下载、合并或检查失败，临时目录保留以便排查；取消任务时清理该任务创建的临时目录。当前不会覆盖已有文件，程序退出后不支持续传。

本地模拟测试覆盖输入、PGC 与流解析、扫码响应、DPAPI、搜索和 WBI 签名、合集与 UP 主投稿分页、收藏夹、备份及关键词规则的持久化/重试/去重、批量调度、aria2 RPC、FFmpeg 输出及 ffprobe 检查。还测试了 FFmpeg 安装的错误校验值、缺失文件、重复请求和并发安装，并通过程序下载固定版本压缩包、验证校验值和启动两个提取出的程序。录播测试覆盖核心初始化、房间及记录持久化、兼容片段合并、不兼容片段拒绝，以及待合并记录重启恢复。已实测公开普通视频下载混流、AV 号解析、两个分 P 并发下载、公开合集与收藏夹读取、一个番剧剧集下载，以及公开直播间短时录制和相邻录制片段自动合并。NVENC、QSV 在本机通过合成视频测试，AMF 在本机不可用。

已实测一个公开视频的封面通过 aria2 下载并经 ffprobe 识别。扫码会话已实测可恢复并显示返回的 Cookie 到期时间；真实登录账号下成功读取创建和收藏的收藏夹及一个收藏夹的跨页内容，并将一个小型收藏夹完整备份至隔离测试目录，重复检查没有重复下载；还成功读取一个公开 UP 主的 497 条投稿。课堂课程已实测分集与权限读取，以及一个免费分集下载混流；已购买课程的完整内容尚未实测。关键词监控使用真实搜索结果，在隔离目录中限制为一个视频测试了下载和重复检查；失效收藏夹过滤仍仅用模拟响应验证。真实直播短录中已在主动切分后强制结束隔离测试进程，并验证重启后的路径恢复、合并及原文件保留。退出保护已在隔离 WPF 窗口中模拟确认和取消，实际消息对话框尚未做完整交互测试。真实付费内容、私人收藏夹长期自动备份、关键词长期监控、直播自然断线、完整合集下载尚未完成端到端验证。首次单视频下载的音频源曾返回 HTTP 567，使用备用地址后重试成功。构建仍有 WPF 异步事件处理器分析警告；不应将此开发版本视为已完成全部功能验证的正式版本。
